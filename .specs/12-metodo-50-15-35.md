# M12 — Método 50-15-35

**Objetivo:** responder "estou seguindo o método 50-15-35 este mês?" — quanto da
renda recebida foi para Necessidades, Desejos e Investimentos/Poupança, comparado às
faixas-alvo de 50%, 15% e 35%.

**Pré-requisitos:** M1–M8 concluídos (schema, categorias, fontes, entradas, saidas).
Pode ser feito em qualquer ordem relativo a M9, M10 e M11 — não depende deles.

**O que é o método 50-15-35:** toda Saída já tem uma Categoria (RN-03 exige isso). A
única peça que falta é agrupar as Categorias existentes em 3 grupos orçamentários —
**Necessidades**, **Desejos** e **Investimentos/Poupança** — e comparar, todo mês,
quanto da renda (Entradas) foi para cada grupo contra a meta de 50/15/35.

---

## Escopo

**Dentro:** classificação de cada Categoria existente num dos 3 grupos, tela de
aderência ao método com barras de meta-vs-real, aviso de categorias não
classificadas.

**Fora:** metas personalizadas (ex: 60-10-30), histórico mês a mês, projeção,
alertas automáticos/notificação. O cálculo é sempre do mês corrente, lido sob
demanda.

---

## Princípio de design

Isto **não** é um novo tipo de dado financeiro — é uma lente sobre dados que já
existem. Nenhuma Entrada ou Saída muda de significado; apenas a Categoria dela passa
a apontar, opcionalmente, para um dos 3 grupos. Por isso:

- Não existe campo novo em `categorias`, `entradas` ou `saidas`. A classificação é
  uma tabela de relação própria (`categoria_grupos`), um por Categoria, independente
  do resto do schema.
- Classificar (ou não) uma Categoria **nunca bloqueia nada** — nem a criação da
  Categoria, nem o registro de uma Saída naquela Categoria. É puramente informativo,
  na mesma linha da RN-06.
- Categoria sem grupo definido continua funcionando normalmente em todo o resto do
  sistema; ela só não entra no cálculo de aderência até ser classificada.

---

## Regras aplicáveis

- **RN-12** (nova) — A classificação de uma Categoria num grupo orçamentário
  (Necessidades/Desejos/Investimentos) é opcional e **nunca bloqueia** a criação de
  Categorias, Entradas ou Saídas. Puramente informativa.
- A base de cálculo dos 100% é o **total de Entradas do mês corrente** (receita do
  mês), não o saldo acumulado e não o total de Saídas.
- Uma Categoria pertence a **no máximo um** grupo. Não há split de categoria entre
  grupos.

## Tarefas

### 12.1 Schema

```sql
-- ============ categoria_grupos (classificação 50-15-35) ============
create type grupo_orcamentario as enum ('necessidades', 'desejos', 'investimentos');

create table categoria_grupos (
  categoria_id uuid primary key references categorias(id) on delete cascade,
  user_id uuid not null references auth.users(id) on delete cascade,
  grupo grupo_orcamentario not null,
  created_at timestamptz not null default now()
);

create index on categoria_grupos (user_id, grupo);

alter table categoria_grupos enable row level security;

create policy "categoria_grupos_select_own" on categoria_grupos
  for select using (user_id = auth.uid());
create policy "categoria_grupos_insert_own" on categoria_grupos
  for insert with check (user_id = auth.uid());
create policy "categoria_grupos_update_own" on categoria_grupos
  for update using (user_id = auth.uid());
create policy "categoria_grupos_delete_own" on categoria_grupos
  for delete using (user_id = auth.uid());
```

Sem campo novo em `categorias`. Uma Categoria sem linha em `categoria_grupos` está
"não classificada".

### 12.2 View `v_adesao_50_15_35`

```sql
create view v_adesao_50_15_35 as
with entradas_mes as (
  select user_id, sum(valor_centavos) as total_centavos
  from entradas
  where data >= date_trunc('month', current_date)
  group by user_id
),
gastos_por_grupo as (
  select
    s.user_id,
    cg.grupo,
    sum(s.valor_total_centavos) as total_centavos
  from saidas s
  join categoria_grupos cg on cg.categoria_id = s.categoria_id
  where s.data >= date_trunc('month', current_date)
  group by s.user_id, cg.grupo
)
select
  em.user_id,
  em.total_centavos                                          as total_entradas_mes_centavos,
  coalesce(g.necessidades, 0)                                 as gasto_necessidades_centavos,
  coalesce(g.desejos, 0)                                      as gasto_desejos_centavos,
  coalesce(g.investimentos, 0)                                as gasto_investimentos_centavos,
  case when em.total_centavos > 0
    then round(coalesce(g.necessidades, 0)::numeric / em.total_centavos * 100, 1)
    else null end                                             as percentual_necessidades,
  case when em.total_centavos > 0
    then round(coalesce(g.desejos, 0)::numeric / em.total_centavos * 100, 1)
    else null end                                             as percentual_desejos,
  case when em.total_centavos > 0
    then round(coalesce(g.investimentos, 0)::numeric / em.total_centavos * 100, 1)
    else null end                                             as percentual_investimentos
from entradas_mes em
left join (
  select
    user_id,
    sum(total_centavos) filter (where grupo = 'necessidades')   as necessidades,
    sum(total_centavos) filter (where grupo = 'desejos')        as desejos,
    sum(total_centavos) filter (where grupo = 'investimentos')  as investimentos
  from gastos_por_grupo
  group by user_id
) g on g.user_id = em.user_id;
```

Metas (50/15/35) são uma constante do frontend, não uma coluna — não variam por
usuário no MVP.

### 12.3 Classificar categorias — dentro de `/categorias`

Não é uma tela nova de cadastro. Em cada linha da lista de Categorias (M5), um
seletor simples:

```
▌ Alimentação                          R$ 340,00 de R$ 1.200   [ Necessidades ▾ ]
▌ Transporte                           R$ 380,00 de R$ 300     [ Necessidades ▾ ]
▌ Lazer                                            R$ 120,00   [ Desejos ▾ ]
▌ Aporte CDB                                        R$ 500,00  [ Investimentos ▾ ]
▌ Presentes                                          R$ 90,00  [ Não classificada ▾ ]
```

- Opções: `Necessidades`, `Desejos`, `Investimentos`, `Não classificada` (remove a
  linha de `categoria_grupos`).
- Mudar o grupo é instantâneo (sem salvar separado), mesma UX de um `Select` inline.
- Categorias arquivadas não aparecem aqui (já estão ocultas por padrão em M5).

```

████████████████████████░░░░░░░░░░░░░░░░░░░░    7% acima da meta

Investimentos                                   15%  de meta 35%
███████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░    20% abaixo da meta

```

- Fonte de dados: `obterAdesao5015_35()` (view `v_adesao_50_15_35`).
- Barra de progresso vai até o maior entre percentual real e meta, para a meta
  sempre ser visível como marcador na régua (não só até 100%).
- Cor da barra: `--color-livre` quando dentro ou abaixo da meta, `--color-alerta`
  quando **Necessidades** ou **Desejos** excedem a meta (gastar mais que o alvo
  nesses dois é o problema); para **Investimentos**, ficar **abaixo** da meta é o
  problema — inverter a lógica de cor (abaixo da meta = `--color-alerta`, na meta ou
  acima = `--color-livre`).
- Se `total_entradas_mes_centavos` for 0 ou nulo (nenhuma Entrada no mês), substituir
  as 3 barras por uma mensagem: "Registre as entradas deste mês para ver sua
  aderência ao método."
- Linha de categorias não classificadas: soma de `v_saldo_categorias` filtrando por
  categorias ausentes em `categoria_grupos`, mês corrente. Omitir a linha se o valor
  for zero.
- Link no menu principal: "Orçamento 50-15-35".

## Critérios de aceite

- [ ] Categoria sem grupo definido continua funcionando em todo o resto do sistema
      (criar Saída, limite mensal, etc.) sem nenhuma diferença de comportamento
- [ ] Classificar/desclassificar uma Categoria não afeta saldo de Fonte nem de
      Categoria
- [ ] Percentuais batem exatamente com `select * from v_adesao_50_15_35`
- [ ] Base de cálculo é o total de Entradas do mês corrente, não o saldo acumulado
- [ ] Necessidades/Desejos acima da meta aparecem em `--color-alerta`;
      Investimentos abaixo da meta aparece em `--color-alerta`
- [ ] Categorias não classificadas somam numa linha separada e não entram em nenhum
      dos 3 percentuais
- [ ] Mês sem nenhuma Entrada mostra mensagem de estado vazio, nunca `NaN%` ou
      divisão por zero
- [ ] Usável em 375px

## Definition of Done

Depois de classificar as Categorias uma vez em `/categorias`, a pergunta "estou
seguindo o 50-15-35 este mês?" é respondível abrindo `/orcamento`, sem nenhuma conta
de cabeça.
